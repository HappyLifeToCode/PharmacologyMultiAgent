# 组会演示手册

适用于双库并行版 `workflow_version=2`。建议 5—7 分钟，以已完成运行回放为主，明确回放不是现场新执行。运行数据和报告不随 GitHub 仓库提供；首次克隆须先完成环境准备并生成一轮合成验证。

截至 2026-09-13，最新完整演练已实际经过 Venny 2.1.0，七个独立模型会话、九阶段成功。会前按 [项目进度与问题](PROJECT_STATUS.md) 对齐讲解；43项自动测试通过是已有验证记录，不表示本次打开文档重新执行了测试。

## 会前准备

1. 按 [快速启动](../README.md#快速启动) 配置环境，在项目根目录启动工作台：

   ```powershell
   .\.venv\Scripts\python.exe server/app.py --port 8766
   ```

2. 打开 [工作台](http://127.0.0.1:8766/)，进入左侧“任务与记录”，在“查看运行”中选择一轮已完成的新版测试数据演练。确认中间显示 GeneCards、OMIM、疾病靶点合并三个独立节点；旧版七节点记录不用于证明双库并行。
3. 提前导出选定运行的离线报告，将下面的 `实际运行编号` 替换为该记录的 run_id：

   ```powershell
   .\.venv\Scripts\python.exe scripts/export_report.py --run 实际运行编号
   ```

   文件保存在 `reports/<run_id>.html`。先本地打开检查，断网时可直接使用。
4. 若展示真实访问或桌面插件计算，另行准备带日期的站点证据、CytoNCA 截图和会话；不要将合成数据图称为数据库结果。
5. 需要展示溯源时，准备已有真实运行的 `data/pharm/<方名>/_meta.md` 和分步目录。合成运行不会写入真实数据归档。

## 逐屏操作与讲法

### 1. 任务输入与依赖流程（约 1 分钟）

操作：展示左侧任务输入、中间依赖流程和右侧阶段详情。需要五类甲状腺疾病时，可点击“填入五类甲状腺疾病”。

> 研究任务描述药材、疾病及分析要求；同一任务可以多次执行，得到不同的运行记录。这里展示的是一次已完成的合成工程验证。当前主流程有协调、药材、GeneCards、OMIM、网络和富集六种角色。药材与两库来源任务可以并行；两库完成后先合并疾病靶点，再与药材取交集，随后并行开展网络和富集分析。

协调角色分别规划和验收，因此完整新运行有七个独立模型会话、九个阶段。疾病合并由程序计算；交集工具由 Playwright 操作 Venny 2.1.0，并由 Python 核对，没有额外模型会话。旧运行仍保留原来的本地交集记录。

首轮芍药甘草汤 × 甲亢和当前多疾病测试任务均属于项目案例。原文方法段没有提供完整药材清单，不宣称案例配方来自该段原文。

### 2. 展示双库并行与独立交接（约 1 分钟）

操作：依次点击 GeneCards 和 OMIM，展示不同会话编号和产物。查看时间线中两支的启动、完成时间；产物点击直接下载，下载后打开相应交接记录。

> GeneCards 与 OMIM 各自执行、检查和保存成果。GeneCards 暂按五类疾病完整检索记录合并计算一个中位数，严格筛选高于中位数的记录；OMIM 提取疾病关联基因。两路通过检查后，程序合并去重。如果其中一库受限，另一库已完成的成果可以保留，补齐条件后再续跑。

补充说明：跨疾病同一基因的分数先分别保留，筛选后去重；该规则暂定，待医生确认。不同会话编号、时间重叠和交接记录一起证明并行执行；会话数量本身不能证明研究结论正确。

### 3. 展示合并与分析产物（约 1—2 分钟）

操作：依次点击“疾病靶点合并”“共同靶点交集”“网络分析”“富集分析”，下载产物或展示离线报告。

展示 Venny 时选择接入后的新运行：下载 `venny.png`、`venny_results.txt` 与 `venny_execution.json`，展示原图、交集名单、实际访问日期和 Python 核对结果。接入前的历史运行只有本地集合图；不能说它已调用 Venny。新测试运行仍需联网访问 Venny，已有 HTML 报告可离线展示。

> 合成测试中，GeneCards 有 6 条测试记录，统一中位数为 6.5，保留 3 条；与 2 个 OMIM 测试靶点合并去重后得到 4 个疾病靶点。再与 5 个药材测试靶点取交集，得到 3 个共同靶点和 2 条测试网络边。这些数量只用于核查程序和交接，不是方剂药理结果。

以上数值对应仓库当前 `examples/fixture.json`；示例改动后应以选定运行的实际产物为准。富集图来自测试术语的本地超几何检验与 BH 校正，不是 DAVID 返回的真实富集结果。

### 4. 展示真实接入与限制（约 1 分钟）

操作：从左侧“任务与记录”选择已有真实来源运行，展示相应访问证据。右侧详情跟随“查看运行”和中间节点；只切换“研究任务”不会切换历史结果。

> 真实模式使用数据库访问记录与合格导入数据。完整上游数据缺失时，正式分析保持受限，下游仍可独立核验分析入口。STRING 已接公开接口，当前自动度值由 NetworkX 计算；CytoNCA 独立安装测试与正式网络自动交接是两个进度。DAVID 的正式导出、背景和统计方法仍需核验。

逐项注明证据访问日期，不将过去的网络限制当作当前站点状态。账号注册、邮箱验证、机构权限和导出权限分别确认。旧版真实运行保持旧图，不代表新版双库并行已采到完整真实数据。

### 5. 展示溯源与下一步（约 1 分钟）

操作：展示 `runs/<run_id>/` 各角色的 attempt 和交接；有真实归档时，再展示 `data/pharm/<方名>/`。

> 原始导出、参数、日期和文件哈希按步骤留存。GeneCards 与 OMIM 的来源证据分开归档，合并结果独立保存；续跑保留旧尝试。下一步补齐真实导出，确认筛选与统计口径，再验收完整科学分析。

需与医生或药理顾问确认：GeneCards 合并查询的中位数口径及跨疾病重复基因处理、BATMAN 推荐阈值与药材命名、DAVID 背景集及检验方法。甲状腺癌 Top 50 与交集外靶点回溯属于另一条补充流程，尚未接入当前 Demo。

| 问题 | 如实回答 |

## 现场新执行与离线备用

需要新执行时，在左侧“新建任务”填写研究信息，将“运行方式”选为“测试数据演练（非研究结果）”，点击“保存并启动”；也可在“任务与记录”选择已保存任务和启动模式后点击运行。模型调用需要等待，不承诺固定耗时。

查看既有运行无需重新调用模型。工作台不可用时，打开准备好的 HTML 报告与截图，并说明来自先前执行。原方案的 995、434、10 不作为本项目必须达到的数量。

演示结论可表述为：“多 Agent 协作与交接、Venny 真实操作已经跑通；完整五库药理研究尚待真实导出、方法确认及两处分析工具接入。”不把本地测试网络或富集图作为原文方法已复现的证据。
