# UI-Agent本地知网文献接入验证

当前网页通过[本地优先流程](LITERATURE_FLOW.md)处理文献。文献辅助默认关闭；启用后先使用已保存的标题摘要，缺少时才自动调用Codex采集，完成后补充独立排序，不获取论文全文。采集及摘要抽取默认使用`gpt-5.6-luna`；CLI手动采集仍需显式`--execute`。所需代码和数据已迁入本项目，不再依赖旧UI-Agent。数据库原支持度/背景排序不改，文献篇数排序独立展示。

2026-10-24后续：新增[本地优先流程后端](LITERATURE_FLOW.md)：靶点结果先返回；本地可用则直接排序，只有题录则仅分析摘要，无文献才排队采集，完成后自动生成独立排序快照。支持正反向、状态、停止和续跑。用户要求本轮先改后端、暂不采集“四方汤”，因此网页尚未接入新自动流程，也没有启动真实采集。

## 使用

首页“查询设置”可勾选“启用知网文献辅助（本地优先）”，默认关闭，影响下一次正向或反向查询；工作台顶部也有正向选项。靶点结果先返回，再独立处理文献，不把文献参数发送给原研究接口。已有会话可直接点击结果下方“启用文献辅助”，无需重算靶点。进度区支持停止/续跑；刷新不会重复启动。旧快照继续恢复原记录，点击“重新读取本地文献”才生成新分析。

来源默认为本项目`data/cnki`，也可在自己的服务终端指定已导出的数据包目录：

```powershell
$env:PHARM_CNKI_DATA_DIR = 'D:\文献数据\cnki'
.\.venv\Scripts\python.exe server/app.py --port 8766
```

生产8766仍由用户原终端管理；加载新版数据路径需用户重启并刷新。读取已有论文不要求模型凭据。无本地数据、文献损坏或疾病目录失败时，文献区域单独说明原因，原数据库查询结果继续保留。方剂按原名查找`data/cnki/cnki_<方剂>/`；单味药材同理，任意多药材组合不套用单味文献。独立交付、一次性迁移和内置采集命令见[CNKI交付说明](CNKI_DELIVERY.md)。

## 接口与快照

- `GET /api/agent/forward/{run_id}/literature`：读取已存在的正向研究归档及本项目数据清单中的`papers.json`、`triples.jsonl`，不接受请求传入外部文件路径。成功后创建独立派生快照。
- `GET /api/agent/forward/{run_id}/literature?snapshot=cnki_<id>`：读取已经保存的文献快照，不重新分析语料；校验内容及原研究归档哈希。
- 快照在`local/agent/literature/<run_id>/`，不会回写原`result.json`或UI-Agent文件。保存题录、支撑句、旧抽取索引、映射状态、规则版本、查询组成上下文、源文件SHA-256和原研究归档SHA-256。
- 浏览器会话只保存启用标记和快照编号，刷新或切换排序后仍查看同一快照。“重新读取本地文献”会创建新快照，旧快照保留；这不是在线更新按钮。
- “导出文献分析JSON”导出此独立快照；原数据库结果JSON导出继续保留原合同。原HTTP研究缓存不混入文献结果，文献文件变化不会让旧快照伪装成新分析。

## 出处核验与排序

旧抽取的“主治/治疗”只作为待核查关系标签，不直接认定疗效。当前接入要求：论文rank、标题及已有URL对应；支撑句能在标题或摘要中定位；病名出现在原文本中；检索主体能在标题/支撑句定位。文本核验仅统一Unicode全半角与空白，不做语义补写。医学关系和研究结论仍待人工复核，`scientific_complete=false`。

同名、加减/加味、联合干预、方名变体、加减情况未知分开记录。同名不保证药味、剂量与本次选定组成相同。`is_modified=false`不能豁免方名核对；温经汤检索中的“温经逐瘀汤”不作为温经汤证据。动物、含患者/临床表述、综述、经验及未知等类型仅依标题摘要做初步规则标记。

关联列表按以下顺序排列，不使用期刊影响因子，也不与靶点分值相加：

1. 同名、未标加减且未识别为联合干预的去重篇数，降序。
2. 全部可追溯关联的去重篇数，降序。
3. 原文病名，确定性并列排序。

文献列表不设Top-N：后端返回全部关联病名及证据，前端遍历完整列表和全部已保存题录。原研究的Top-K及是否进入数据库展示列表都不截断文献列表。新的关键词全量采集模式也不改变这三项排序规则；全量只指采集当时可访问的关键词结果，现有历史样本不标成全量。

界面将原来的“同名”改为“方名一致且未标加减/联合”，并解释全部关联篇数及同数并列。“尚无精确疾病映射”改为“已找到文献关联，暂未匹配数据库疾病编号”，不影响查看论文和文献篇数排序。来源和记录编号收进版本详情，历史快照仅更新展示文字，不改原数据。

DOI可用时优先作为论文身份，否则使用归一化标题、作者、来源和日期；不以检索rank或带时效token的URL计篇数。一篇的多条支撑句不重复加分，同一篇出现身份冲突时保守处理，不计入同名直接篇数。这里的篇数是检索频次，不是临床证据等级或治疗概率。

病名使用完整Open Targets/Monarch疾病目录进行精确名称/别名匹配，不限原来返回的Top-K。`chinese_terms.json`只登记明确中文—英文译名，并仍要求精确命中目录；不会用翻译覆盖已有歧义，不把功能性便秘或慢传输型便秘换成普通便秘。未映射和多候选病名保留原文，界面明确显示待确认。映射成功也不等于本次已经取得该病全部靶点证据。

## 本机验证与下一步

四个内置方剂各20篇，共80篇题录、79篇有摘要。当前规则得到65组文献疾病关联：21组可精确对齐、3组有歧义、41组未精确映射；13条旧疾病关系来源未纳入（可能涉及其他方剂、文本定位等原因，不等于13篇论文无效）。温经汤的“痛经”关联有2篇同名文献；半夏的“偏头痛”保留目录歧义；济川煎的慢传输/功能性便秘保留原文，不改成父病。

这些数据只是旧采集的知网相关度前20篇样本，不能代表全部文献；缺摘要、未采到、无法映射、没有关联是不同状态，不当作负证据。现阶段可以验证接口和追溯链路，尚不能据此替换默认疾病排序。

可复核离线接入：

```powershell
.\.venv\Scripts\python.exe scripts/validate_cnki_bridge.py --output local/checks/cnki-local-bridge
```

本轮证据在`local/checks/cnki-integration-20261023/`，正式四方语料核对见`real-corpus/summary.json`。下一步应先完善疾病映射和人工抽检、明确文献相关度评价标准，再验证按需在线采集的队列、取消、增量和锁协议；本轮没有启动在线采集。

工程回归：Python全量348 passed、3 skipped；既有Node图连接5项通过。1440/390首页和工作台实际本地适配验证通过，原8份语料和研究响应SHA-256未变。数据库计算只使用真实旧归档回放，未新跑药理研究；在线采集能力未验证，也未因此标记科学验收完成。
