# Agent 工作分配与模块认领

本文面向项目开发者，定义各 Agent 的开发边界、交接对象及验收条件。开发负责人是实现和维护模块的团队成员；Agent 是运行时执行任务的程序角色。角色数量不等于所需开发人数，一名成员可以承担多个模块。

上表按团队开发模块组织，疾病模块内部包含两个运行时角色。新版共六种 Agent 角色、七个模型会话、九个阶段；协调规划与验收各占一个会话，疾病合并由程序完成，交集由程序操作官方 Venny 2.1.0 并核对。负责人字段沿用团队认领，不因角色拆分自动分配新成员。

## 1. 协调 Agent

**输入：** 方剂、药材、疾病、分析配置和运行状态。

**开发任务：** 实现独立 Agent 任务的调度、依赖检查、状态管理、交接校验、有限重试和断点续跑；汇总经过验证的结果。为每个任务提供 run_id、task_id 和 attempt，记录实际工具调用及交接事件。浏览器会话应按任务隔离，共享登录态或资源时显式处理互斥。

**交付：** 调度入口、任务状态与事件记录、产物索引及汇总报告入口。

当前依赖顺序与启动控制由执行器代码定义，协调模型负责规划与验收意见。动态修改任务图、自动安排返工等能力属于后续开发目标，不能仅凭角色说明宣称已实现。

**验收：** 按依赖并行启动药材、GeneCards、OMIM 来源任务，疾病两库通过检查后合并，再取药材/疾病交集并启动两路分析；失败任务不会标记成功，阻塞项能定位到来源。恢复运行保留历史，输入或参数变化时不错误复用旧结果。不得用协调模型生成的虚构数据补齐缺失结果。

## 2. 药材靶点 Agent

**输入：** 药材名单、查询配置和已确认的 BATMAN 筛选规则。

**开发任务：** 核验 BATMAN 当前入口与导出格式，查询药材、成分及预测靶点，保存原始结果；处理药材名称和炮制形式匹配，调用共享模块完成规范化和筛选。

**交付：** 原始导出、药材—成分—靶点关系表、靶点清单、阈值及来源记录；交给共享数据处理模块。

**验收：** 可从处理后靶点回溯药材、成分和原始记录；未确认阈值和歧义匹配明确标注，不能擅自用其他药材替代。无结果与访问失败分开记录。

## 3. 疾病靶点模块（两个并行子 Agent）

**输入：** 疾病关键词和筛选配置。

运行时拆分为 [GeneCards Agent](../agents/genecards_targets.md) 与 [OMIM Agent](../agents/omim_targets.md)，分别拥有独立会话、状态、来源和产物。两路均通过检查后，由程序合并去重，不额外启动疾病合并 Agent。模块负责人沿用上面的认领表；子模块归属由团队自行确定。

GeneCards 暂按合并全部所选疾病完整记录后统一计算中位数，保留严格大于中位数的记录；跨疾病同一基因分数保留，筛选后去重。`genecards_median_status=provisional` 表示待医生确认。OMIM 不使用 GeneCards 分数筛选。

**开发任务：** 分别接入 GeneCards、OMIM；核验完整结果获取能力，提取 GeneCards relevance score 及 OMIM 疾病—基因关联；调用共享模块筛选、映射、合并并去重。

**交付：** 两库原始导出、完整性记录、中位数及筛选表、OMIM 关联证据、带来源标记的疾病靶点清单；交给共享数据处理模块。

| 执行阶段 | 会话与输入 | 输出和下游 |
|---|---|---|
| genecards_targets | 独立会话；任务疾病、完整 GeneCards 记录、来源与映射依据 | 筛选后 targets.json、中位数、记录数及暂定规则，交给疾病合并 |
| omim_targets | 独立会话；任务疾病、OMIM 关联记录、来源与映射依据 | targets.json 和来源记录，交给疾病合并 |
| disease_targets | 确定性程序；两支通过检查的 targets.json | 合并 genes、gene_sources 和计数，供共同靶点交集使用 |

**验收：** GeneCards 使用完整查询结果计算中位数并严格筛选大于中位数的记录；分页不完整时不得宣称完成。OMIM 表型条目编号不得当作基因标识。合并结果可回溯两库来源。

## 4. 网络分析 Agent

**输入：** 校验后的共同靶点、物种和 STRING 参数。

**开发任务：** 接入 STRING，检查标识映射和网络参数，保存节点、边及缺失节点；接通 Cytoscape/CytoNCA，生成拓扑指标和网络图。

**交付：** 映射报告、节点及边表、拓扑指标、网络图和参数记录；交给协调 Agent 汇总。

**验收：** 记录 Homo sapiens、置信度 0.900 和额外节点设置；保留孤立及未识别节点的说明，图、节点表和度值表可对应。未使用 CytoNCA 时不得把其他算法结果标为 CytoNCA 输出。

## 5. 富集分析 Agent

**输入：** 与网络分支相同的共同靶点清单、背景集和富集参数。

**开发任务：** 接入 DAVID，核验识别率、背景集、GO BP/CC/MF 与 KEGG 注释、实际检验方法和 BH 校正字段；保存完整结果并生成 FDR < 0.05 的筛选结果及展示图。

**交付：** 识别报告、完整及筛选后的富集表、图和统计参数；交给协调 Agent 汇总。

**验收：** 显著条目能回查原始统计值；实际检验与方案指定方法不一致时说明差异，不直接改名为超几何检验。零显著结果如实保留；不自行改用网络 Top 靶点替换交集。

## 6. 共享数据处理与校验

由团队明确一名负责人维护，两路靶点模块共同评审接口，避免各自实现不同的规范化口径。

**开发任务：** 输入解析、数值和缺失值校验、HGNC 映射、中位数计算、去重、Venny 2.1.0 浏览器适配、原图保存、交集独立核对、失败拦截、文件哈希与交接清单校验。先检查真实导出再确定具体列名。

**交付与验收：** 统一的处理接口和异常记录；相同输入及参数产生一致结果；原始 ID、映射来源和歧义项可查，不能将丢失记录静默当作正常筛选。为关键计算提供小型可复核样本，合成样本不得混入真实结果。

Venny 归本共享模块维护：保存官方原图、三个集合区域原文、输入与访问记录，Python 仅作独立核对。网络异常、结果不一致或一侧名单为空时明确失败；两非空集合无交集时返回0并跳过后续。不得用本地绘图顶替或复用旧下游成功状态。

## 协作顺序

1. 协调和共享模块负责人共同确定任务与交接接口，各模块负责人核验相应站点的访问和导出条件。
2. 药材、GeneCards、OMIM 来源能力可并行开发；疾病模块先分别验收，再联调合并。网络、富集模块可使用明确标记的小样本验证接入，但这不代表真实 Demo 完成。
3. 两路真实靶点结果通过校验后，生成共同靶点，再联调网络与富集分支。
4. 完成独立模块验收后，进行端到端运行、断点恢复和报告核对。

协作不要求所有任务同时执行；存在输入依赖的步骤必须等待上游交付。对站点访问频率和共享会话分别控制。

## 统一交付要求

- 认领模块时填写负责人；提交内容包括实现、配置示例、使用说明和可复核的验证记录。
- 遵守 [数据交接约定](DATA_CONTRACT.md)，接口变动须与上下游对齐并更新文档。
- 无法访问、登录失败、结果不完整、基因无法映射等情况必须返回明确状态及原因；不得以空表伪装成功。
- 凭据、原始研究数据和完整执行日志保存在本地或约定共享渠道；仓库示例去除登录态和敏感信息。
- 整体验收同时检查分析结果与真实协作记录，详见 [Demo 实施计划](DEMO_PLAN.md)。
