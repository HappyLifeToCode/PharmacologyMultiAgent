# 启动与使用

## 当前能力

两条流水线：discovery（本地数据预检 → 药材靶点解析 → 疾病反向查询 → 程序验收与报告）与 analysis（候选疾病的机制分析：共同靶点 → 网络 → 富集 → 验收）。计算全程确定性程序；live 默认启用六个 Codex 核验会话（多 Agent 编排，程序计算·Agent 核验）；本地数据缺失时阶段 blocked 并给出指引。

第三阶段可查询 Open Targets：留空疾病范围时输入 BATMAN 靶点，填写范围时按疾病查询；默认读取本地快照，设置 `PHARM_OPEN_TARGETS_MODE=online` 才调用 GraphQL API。GeneCards/OMIM 与人机协助采集已移除。

## 1. 启动页面

浏览器标签页图标（favicon）使用 `server/static/icons/favicon.svg`，首页和工作台在 HTML 的 `<head>` 中通过 `<link rel="icon">` 指向它。默认沿用项目叶子标识；更换图标可修改这个 SVG 文件。首次更新包含服务端图标白名单时，在用户自己的终端按 Ctrl+C 后重新执行启动命令，再刷新页面；浏览器仍缓存旧图标时关闭标签页后重新打开。生产服务继续由用户终端管理。

首次使用先完成 [README 的环境安装](../README.md#快速启动)。以下命令在项目根目录的 PowerShell 中执行，使用项目 `.venv`；已有环境可替换解释器路径。

```powershell
.\.venv\Scripts\python.exe server/app.py --port 8766
```

打开 [本机对话首页](http://127.0.0.1:8766)。也可以使用 `scripts/start_demo.ps1`。服务仅监听本机。下面的任务、运行和机制分析操作请进入 [研究工作台](http://127.0.0.1:8766/workbench)。

### 简洁会话首页

正向新查询默认展示具体疾病候选，将“肿瘤、癌症”等已识别大类单列在可展开的“大类参考”中。候选按完整 Open Targets 背景校正匹配度排序，原支持度、原排序摘要和逐条证据可继续查看；缺少背景会明确提示。旧归档保留旧排序，重新查询才使用新规则。首次需建立完整背景，等待时页面会显示该阶段；该匹配度不是疗效概率，详见 [排序说明](FORWARD_RANKING.md)。本次包含后端改动，需在用户原终端重启服务后刷新。

查询中会显示当前阶段、真实分片/行数及耗时；刷新后继续读取同一任务。相同输入和参数在数据/代码版本一致时可复用成功结果，页面会显示原计算时间和运行编号；新运行仍单独归档。首次查询需要完整计算，缓存损坏或来源变化自动重算，不使用失败半成品。可用 `PHARM_AGENT_QUERY_CACHE=false` 关闭缓存；详见 [查询执行说明](QUERY_EXECUTION.md)。这次包含后端改动，请在自己的服务终端按 Ctrl+C 后重新执行原启动命令。

2026-10-14 疾病到药材入口：输入“查询肺腺癌关联哪些药材”，也可使用中文名、英文名或 MONDO/EFO ID。输入框上方支持自动、正向、反向方向选择。疾病有歧义先选择，未确认不启动计算；第一版单疾病、BATMAN known-only，未知中文名可改用英文或 ID。结果可追问“展开第一个药材的证据”“查看疾病靶点”“查看匹配指标”，并导出完整 JSON。返回数量不裁剪疾病靶点，反向不使用正向 heuristic_v2；数据与覆盖率定义见 [疾病到药材查询](DISEASE_TO_HERB.md)。

反向首次有效查询自动建立 BATMAN 派生索引，也可先运行 `.\.venv\Scripts\python.exe -m pharm.batman.reverse_index`。需要本地药材和 known 文件，索引按源文件哈希复用，不联网下载或自动改用预测关系。生产服务继续在用户终端运行；更新后由用户 Ctrl+C、按原命令重启，不重复启动后台 8766。

2026-10-14 方剂目录扩展：将官方方剂组成文件 `formula_browse.txt` 放入当前 BATMAN 数据目录（默认 `data/batman/v2.0/`），重启服务。输入“四物汤”等名称后，同名不同组成会弹出药材清单供选择，不按第一条自动计算；同名同组成合并。可以修改为本次实际药材组合，勾选记住后保存为本机默认。未匹配的名称会提示，需修改或明确按已匹配部分继续。温经汤等四方保持原组成；要切换或编辑，先输入方剂名，再点“选择/修改组成”。方剂表未提供出处，页面不会把记录冒充某古籍的标准方。数据更新后保存的默认组成需要重新核对。

现在可直接输入“温经汤可能与哪些疾病有关？”，后端自动提取已收录方剂，并衔接药材→成分→靶点查询。多个方剂或加减方会要求明确输入，不擅自用原方替代。

正向助手 BATMAN 选路为：已配置本地全量数据 → 已取得的官方本地缓存 → 官网公开下载。只有必需文件缺失才触发回退；真实未命中、空结果或损坏文件不会自动改来源。首次下载可能较慢，官网不可达或无可识别链接时会明确报错。来源、下载 URL、时间和哈希随结果保存；仍是 known-only，不自动启用预测记录。既有任务流水线仍保留本地预检。详见 README 的“正向助手：自然问句与 BATMAN 本地优先”。

输入“帮我看看温经汤关联哪些候选疾病”或“白芍、甘草”，Enter 发送，Shift+Enter 换行。候选疾病和证据直接显示在回复中，可继续输入“展开第一个疾病的证据”“查看药材组成”“解释匹配支持度”，或点击对应按钮。查询设置控制返回数量和 BATMAN 阈值。首页复用现有正向查询，不调用旧任务接口，不改变评分或数据源，也不提供通用模型聊天。

侧栏支持新建、搜索、切换和删除会话。文字和运行编号存于当前浏览器，结果从本机归档重新读取；删除会话不会删除归档。可导出当前结果 JSON。查询失败、归档缺失和页面关闭造成的中断如实提示，不自动补造结果。以下“正向 Agent 对话框”为保留工作台的操作说明。

疾病英文名后会追加中文名，首页和工作台一致；历史结果刷新即可补充显示，无需重新查询。未有可靠匹配的词条标为“中文名未收录”，词表加载失败标为“中文名暂不可用”。中文译名不改变原始疾病 ID 和研究数据。

“研究工作台”在新标签页打开。在项目内切换对话/工作台、切换浏览器标签或刷新，后台继续原查询；返回时自动恢复同一请求，不重复提交。关闭承载查询的页签后约 10 秒终止对应查询，服务和其他查询保持运行。页面连接持续中断超过缓冲期，也按页签断开处理。

连接报错时可点“恢复原查询”只读取状态/结果；主动点“重新查询”，服务先确认旧查询已停止，再从头开始新的，不自动续算中间文件。已完成结果读取失败时点“重新读取结果”，只重新读取归档。旧版没有请求编号的失败记录无法定向恢复/取消，请先核对后台运行；更新后按启动命令重启服务并刷新页面。

### 团队真实数据试测清单

在已有真实 BATMAN、Open Targets 和 Monarch 数据的机器上更新代码，重启服务并刷新首页。此次改造未包含研究数据或本机配置，请保留各自的数据目录与配置。

1. 查询“温经汤”和“白芍、甘草”，核对展开组成、BATMAN 实际命中、候选数量和数据源状态；记录查询耗时。
2. 追问“展开第一个疾病的证据”“查看药材组成”“解释匹配支持度”，抽查基因、来源与原始分值是否和返回结果一致；核对支持度不是治疗概率。
3. 调整返回数量再查询，确认新参数生效、旧结果不变。当前正向查询采用 known-only，阈值会记录但不会开启预测靶点或改变已知证据结果。导出 JSON，核对运行编号与后端归档一致。
4. 刷新页面、切换历史会话，检查结果恢复；在手机窄屏检查长列表和展开证据，输入框应始终可用。
5. 打开 `/workbench` 检查原任务功能未受影响。数据源缺失、失败或未命中时应如实提示，不应显示伪造成功。

反馈请附提交版本、输入与参数、运行编号、耗时、异常截图和相关服务日志；不要上传凭据或未经许可的研究数据。通过试测只代表对应真实数据工程链路通过，不等于科学验收。

### 正向 Agent 对话框

页面顶部的“正向 Agent：方剂/药材 → 候选疾病”用于当前优先开发的正向链路。直接输入“温经汤”，设置“返回数量”，点击“查询候选疾病”（或按 `Ctrl+Enter`），后端会自动展开 12 味药材并继续查询，无需操作下方任务面板。也支持输入一个或多个药材名称，每行一个或用逗号/顿号分隔。

当前识别本地方剂表和原四方剂，一次仅输入一个方剂名。同名异方先选择或编辑组成，确认后才启动计算；未收录方剂或加减方需输入实际药材清单，程序不猜测组成。查询结果上方显示展开的药材；点击“查看药材组成与 BATMAN 命中”可核对原始名称、映射说明、实际命中名、成分数和靶点关系数。未命中药材如实展示，不补造靶点。内置组成来源仍待研究者确认；旧任务面板的四方剂下拉不扩展。

查询调用 `POST /api/agent/forward`，对话框发送 `{"text":"温经汤","top_k":10}`，输入识别由后端完成；也可通过 API 显式传入 `formula` 或 `herbs`，三者只能选择一种。默认读取本地 BATMAN、Open Targets 26.09 快照和 Monarch 2026-10-07 快照。结果展示候选疾病、匹配靶点、输入覆盖率、来源计数、逐条证据和 `heuristic_v2` 排序分数。该分数只是候选关联排序，不是治疗有效率、疗效概率或用药建议。

更新代码后需重启原服务，再刷新页面；启动命令仍为上文的 `server/app.py --port 8766`。

多味方剂需处理较多关联记录，本机查询可能需要数分钟到十几分钟；按钮显示“查询中…”时请等待。后端逐行处理采集文件，结果只展示设置数量的候选，完整来源记录仍保留。

当前对话框不执行网络分析、富集分析或临床治疗证据检索；这些功能仍通过已有任务/机制分析流程使用。

## 2. 提交任务

左侧"新建任务"：选择内置方剂（自动填入组成，可增删编辑）或"自由药材组合"手工填写药材（每行一味）；阈值默认 0.84；选择运行方式；可选研究说明。

- **保存任务**：写入 `tasks/tasks.local.jsonl`（Git 忽略）；相同内容重复保存复用同一任务（task_id 为内容哈希）。
- **保存并启动**：保存后立即启动一次运行。保存与启动是两个步骤；启动失败时已保存内容保留。

| 方式 | 实际执行 | 能证明什么 |
|---|---|---|
| live（本地数据反查） | 读取本机 BATMAN 全量文件与疾病索引；默认启用 Agent 核验会话；缺失时对应阶段 blocked + guidance，不伪造 | 真实本地数据链路与真实缺口 |
| fixture（合成工程验证） | 固定合成靶点与合成索引，全程标注 synthetic_engineering，不访问外网、不调模型 | 工程流程可运行；不代表任何药理结果 |

**多 Agent 开关**：任务字段 `agents`（live 默认 true、fixture 强制 false）。live + agents=true 需要可用的 Codex CLI 与 profile（见 [Codex 执行配置](CODEX_RUNTIME.md)）；环境不可用时运行直接 failed 并提示改用 agents=false——纯程序 live 不需要模型服务，报告注明"无 Agent 核验"。

也可以从命令行运行：

```powershell
.\.venv\Scripts\python.exe scripts/run_tasks.py --task <task_id>
.\.venv\Scripts\python.exe scripts/run_tasks.py --resume <run_id>
```

同一时刻只允许一个完整运行（`runs/.runner.lock`）。

## 3. 查看与恢复

- 中间栏选择运行，阶段图按状态着色（succeeded 绿 / failed 红 / blocked·partial 橙 / running 蓝）；点击阶段节点，右栏显示状态、摘要、blockers、findings 与产物下载。analysis 运行的阶段图为共同靶点提取 → 网络分析 → 富集分析 → 验收与报告，运行项带"机制分析·疾病名"徽标。
- "疾病反向查询"阶段详情内含候选疾病表、未命中靶点与未命中药材清单；report.md 在运行级下载。
- **置信度阅读**：候选疾病表的"置信度"列是程序计算的透明启发式（heuristic_v2：log 匹配数、输入/疾病覆盖率、证据质量的加权和），**非统计检验，仅供排序参考；列表是固定顺序，不是疗效排名**。点击置信度数值展开四个组件明细（null 组件不参与加权）；零匹配疾病置信度为 0 并如实显示。
- **机制分析**：候选疾病表中匹配靶点 > 0 的行有"机制分析"按钮，确认后创建 analysis 运行（共同靶点→网络→富集→验收）并自动选中；零匹配行不显示按钮。
- **Agent 核验**：阶段详情显示各阶段 Agent 核验结论（角色、状态、把握自评高/中/低、理由、会话编号）；会话未完成时如实显示错误，阶段状态以程序结果为准。
- 事件列表滚动显示阶段与工具事件；页面每 5 秒轮询。
- blocked/failed 的运行显示"恢复运行"；恢复只复用输入、代码、数据与产物哈希全一致的成功阶段，其余阶段新建 attempt 重跑（验收每次重核）。补齐本地数据后恢复，受阻阶段会检测到签名变化而自动重跑；修改 `agents/*.md` 提示词也会使对应阶段重跑（预期）。
- 异常关闭留下运行锁时，先查看 `runs/.runner.lock` 中的 PID 并确认原进程已退出，再删除该锁。

## 4. Open Targets 数据查询

勾选“启用 Open Targets 数据查询”。疾病范围可留空，第三阶段自动使用药材靶点发现候选疾病。填写疾病范围用于限定查询。

本地快照配置与独立命令见 [导入说明](IMPORTS.md)。当前模式由服务环境变量选择：local 读取快照，online 使用 API；查询失败保留中间产物，检查配置或连接后恢复。旧在线来源任务需要重新保存，不自动改写历史快照。

## 5. 环境检查与测试

```powershell

.\.venv\Scripts\python.exe -m pytest tests/ -q
```
