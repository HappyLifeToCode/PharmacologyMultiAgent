# 正向候选疾病证据图

在首页候选疾病旁点击“查看证据”，或在工作台顶部正向查询中点击候选行，证据表上方显示“这条疾病关联如何得到”。原支持度、背景校正、大类及OT分层参考使用同一展示组件，并始终读取被点击疾病的证据。

图按四列组织：药材 → 成分 → 靶点 → 候选疾病。它解释本次数据库检索如何得到候选，不表示因果、激活/抑制或治疗作用。

## 使用

- 搜索或选择一个靶点，查看该靶点能追溯到哪些药材和成分。靶点按符号排列，仅是浏览顺序，不表示关键靶点排名。
- 每组最多显示8条唯一“药材—成分—当前靶点”路径，用上一组/下一组查看其余路径。图上明确显示路径总数、当前范围、疾病关联记录数；不会把显示的一组冒充完整网络。
- 可筛选疾病证据来源。点击节点或连线会突出相应路径，在下方显示对应的BATMAN关系、Open Targets或Monarch记录、原始分值及归档数组位置。完整名称可通过节点提示和详情查看。
- 同一成分CID可连接多味药材；同名不同CID保持独立。缺少CID的记录各自展示，不按名称合并。同一条可视路径的重复原始行仍保留在详情中。
- 实线表示含known记录，虚线表示仅predicted或未标注，紫线表示疾病关联；线宽没有分值含义。新查询继续known-only；旧归档若含predicted，按归档原值如实显示。
- “下载当前图 SVG”导出当前靶点和路径分组，包含范围、来源、图例和关联边界，可供汇报使用。原JSON导出仍包含原始研究字段与完整返回证据。
- 手机上在图内左右滚动，页面本身不横向溢出。

## 数据与边界

图只连接归档中的`herb_relations`和所选候选的`evidence`，以精确`gene_symbol`连接，不自动映射基因别名，不混合另一疾病的记录。药材保留原输入及实际BATMAN命中名，中文标签共用已有明确显示映射。旧归档缺药材/成分或疾病逐条证据时显示缺口，不调用数据库补算，不虚构路径。

节点数按当前候选能追溯的归档身份计算，不代表全部输入药材、药材全部成分或疾病完整靶点数。分组、搜索、来源筛选和下载均在本地页面完成，不创建研究请求，不改候选排名、分值、缓存键、后端计算、历史文件或任务接续规则。`scientific_complete`仍为`false`。

实现为首页/工作台共用的`server/static/evidence-graph.js`与CSS，没有外部图形库或查询时联网依赖。服务器增加两个明确静态资源路由；首次升级需要在用户自己的终端重启服务，再刷新页面。生产8766仍由用户终端管理。

原靶点图开发时，论文标题/摘要检索与文献排序曾暂缓；后续 CNKI 图进展见下方补充。

开发验证：`node --test tests/evidence_graph.test.cjs`检查身份连接、重复记录、精确符号/疾病、缺CID与缺路径、完整分页及预测证据保留；Python回归仍执行`python -m pytest tests -q`。
