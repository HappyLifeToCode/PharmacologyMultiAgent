# 本地数据与候选疾病发现：目标调整记录

日期：2026-09-15。依据用户转述的组会要求。本文记录新方向与工程建议，不代表研究参数已经确认，也不代表以下改造已经实现。

## 已明确的目标

最终将所需数据库数据保存到本地，由 Agent 调用本地查询工具。任务从“输入药材和疾病，分析共同靶点”调整为“根据输入药材的成分及其靶点，寻找对应的候选疾病”。

输出应称为潜在适应证或候选疾病。靶点关联、网络中心性与通路富集不能单独证明药材能够治疗某疾病。是否属于老药新用，还需要明确既有适应证及新增适应证的证据。

## 建议主流程

药材／用户提供的成分 → 成分核对 → 成分关联靶点 → 本地靶点—疾病反向查询 → 按疾病汇总证据 → 候选疾病优先级评估 → 网络与富集解释 → 可追溯报告。

疾病不再是新流程的必填输入；可以在后续作为可选的检索范围约束。保留旧工作流及历史运行的读取、归档和恢复能力，新流程采用独立版本。

不能先把所有疾病靶点合并成一个集合再排序疾病，否则会丢失靶点属于哪个疾病及其来源的信息。共同靶点仍可使用，但应在候选疾病层面分别计算。

## 本地数据层建议

| 数据关系 | 至少保留的信息 | 用途 |
| --- | --- | --- |
| 药材—成分 | 规范名称、别名、成分标识、来源 | 输入匹配及溯源 |
| 成分—靶点 | 成分与基因／蛋白标识、物种、实验或预测证据、原始分值及作用方向（如有） | 构建输入靶点集合 |
| 靶点—疾病 | 规范疾病标识、疾病名称、靶点标识、关联类型、证据及来源 | 反查疾病并逐病种聚合 |
| 蛋白关联及功能注释 | PPI 边与分值、GO／通路成员、物种及版本 | 本地网络和富集分析 |

数据库准备与运行时查询分开：下载或合规导入 → 标识统一与校验 → 建立索引 → 发布数据版本；Agent 通过限定输入输出的工具查询该版本。保留来源、下载日期、许可证信息、原始文件校验值与转换记录。

存储引擎根据实际数据规模选定；SQLite 或 DuckDB 可作为候选，不在尚未核实数据规模时锁定。必须先核实各来源的官方批量下载能力及使用条件，不能把网页可访问等同于可以完整下载。原计划中的数据库也不应自动成为新流程的必选来源。

## 现有成果如何复用

- 多 Agent 调度、任务归档、错误状态、来源记录和报告能力可以沿用；新流程需要调整任务输入、数据契约及依赖图。
- Cytoscape／CytoNCA 自动交接及非加权 Degree 已完成技术验证，可以继续用于候选疾病相关靶点网络。Degree 不直接决定疾病治疗价值。
- STRING 当前通过远程 API 获取数据；本地化需要新增本地数据读取与标识映射适配。
- DAVID 当前是真实远程服务接入，不属于本地富集。若要求富集也本地运行，需要增加本地注释与统计实现，并明确其方法和版本，不能标记为 DAVID 官方结果。
- 旧流程的疾病合并与 Venny 交集不再是新流程的固定前置步骤，可用于候选疾病的后续解释。

## 开发顺序与验收

1. 核实数据源：形成下载方式、许可、覆盖范围、字段、体量和版本清单；落实至少一组可用的成分—靶点及靶点—疾病数据。
2. 建立本地数据导入与查询：验证标识映射、重复与缺失记录、物种边界、数据来源及版本追踪。
3. 实现疾病反查小样本：用显式工程样本验证一个靶点关联多种疾病、同一疾病多靶点、别名映射、重复证据及无匹配结果；手工核对查询结果。
4. 集成新调度流程：支持未输入疾病的任务，输出逐疾病的靶点与证据表；保留旧流程兼容性。
5. 接入网络与富集解释：明确每次分析针对哪些靶点；富集背景应与输入靶点的产生和可检出范围相符。
6. 方法确认后再实现正式排序与研究验证；随后考虑产物验收平台。

小样本通过仅证明查询和调度正确，不能作为真实疗效验证。疾病排序不能只使用共同靶点数量：需要考虑注释规模偏差、证据质量、疾病粒度及药物作用方向；不同来源的分值不能直接相加。

## 尚待明确

- 数据来源、允许的使用方式、物种及疾病检索范围。
- 输入成分是用户提供、数据库补全，还是两者均支持；实验与预测靶点如何区分和使用。
- 疾病优先级评价方法、阈值、证据要求及验证方案。现有任务默认参数不自动沿用为新研究口径。
- “数据本地化”是否也要求网络／富集计算完全离线；模型服务是否允许联网需要单独界定。
