# 文献模块独立交付

## 2026-10-26 拒绝访问后的自动切换

新任务先使用无界面专用Edge。主文档导航（包括检索跳转及详情页）实际返回HTTP 403时，在同一任务、同一项目资料目录中自动正常切换一次到可见模式，继续读取已保存的进度。已切换的任务续跑沿用可见模式，新任务仍先后台。429限流、超时、登录或验证码不触发自动切换；有头模式仍拒绝或出现登录/验证码时暂停并保留可见页面，等待手动处理。不会改User-Agent或伪装浏览器，也不会自动处理验证码。

这次“一贯煎”实际复现了主页200→跳转302→检索403，Chromium将它替换成chrome-error内部页；旧程序只等DOM，因而误报search_results_unavailable。现在按主文档响应判断，忽略子资源/iframe错误，并区分403、429和检索超时。私有diagnostic仅记录主机/路径/状态码，不记录查询token、HTML或表单值。

任务状态公开browser_mode及browser_fallback，页面说明自动切换情况。切换必须由持有本进程采集锁的工作线程执行，手动打开接口仍拒绝打断活动采集。已保存论文和完整页码核对继续复用，全量要求、模型、标题摘要范围及文献排序不变。

本项目已拥有文献分析、数据校验/导入/打包、采集执行器、标题摘要关系抽取和提示模板。日常运行只读本项目`data/cnki`或显式配置的`PHARM_CNKI_DATA_DIR`，不再寻找同级UI-Agent，也不再使用`PHARM_CNKI_PROJECT_DIR`。

更新代码、导入数据并重启服务加载新版后，旧UI-Agent文件夹可以移走或自行删除，本项目的本地文献功能不受影响。Python、Codex CLI、Node/浏览器等运行环境是独立的软件依赖，不属于旧工程源码。

## 本项目自带的采集代码

`pharm/literature/collector.py`保留逐篇保存、增量题录、断点续跑、关系抽取与合并流程，入口为`scripts/collect_cnki.py`。2026-10-25起，`browser_collector.py`通过Python Playwright顺序读取正常检索页和详情页，程序核验可见验证、页码、位置、标题及完整摘要；不调用隐藏接口、不获取正文。标题摘要关系抽取仍调用Codex CLI `gpt-5.6-luna`，每批最多8篇，逐篇核对原句。可用`CODEX_BIN`指定Codex可执行文件，新任务可用`--model`显式覆盖模型；续跑沿用任务保存的模型。模型不可用时失败并保留任务，不自动换模型。

原句采用同篇编号：T为标题，A编号为该篇摘要的原句。模型选择支撑句编号，程序从原文复制后再校验，不让模型改写引文。未知编号拒绝；批量格式或引用不合格仅纠正一次，仍失败则保留进度，不发布。已有通过的抽取缓存继续复用，外部triples数据格式不变；模型输入不含正文或摘要节选。

新记录的加减标记同时检查标题和完整摘要：标题明确标加味/加减/化裁/合方，或摘要中本次关键词紧邻这些标记时记为加减；其他含义不明确的加减提及记为未知，不计入“方名一致且未标加减/联合”篇数。没有这些文字标记不代表药味、剂量已核实。原五组历史记录不回写，篇数排序公式不变。

默认只准备任务，不调用模型或浏览器：

```powershell
.\.venv\Scripts\python.exe scripts/collect_cnki.py --keyword 温经汤
.\.venv\Scripts\python.exe scripts/collect_cnki.py --check-runtime
.\.venv\Scripts\python.exe scripts/collect_cnki.py --print-mcp-config
```

第三条命令保留输出旧模型浏览器调试路径的Codex `mcp_servers`配置样例，正常采集已改由程序执行，不需模型控制浏览器。项目不写用户全局配置或模型密钥。摘要抽取仅接收rank、标题和摘要，按次设置较低推理强度，不额外配置浏览器。`--check-runtime`只检查本机依赖位置，不代表账户或知网已连通。Codex参数依据[官方CLI说明](https://developers.openai.com/codex/cli/reference)。

新任务优先在无界面的项目专用Edge中运行，403自动切换策略见上节；复用`local/agent/cnki-browser/profile`，关闭或重启后也沿用该目录。需要安装Microsoft Edge。需要手动登录或验证时，在网页错误区点击“打开登录/验证窗口”，或执行：

```powershell
.\.venv\Scripts\python.exe scripts/open_cnki_browser.py
```

人工窗口与后台使用同一项目专用资料目录，切换前正常关闭并保存本项目的已验证会话，不复制常用浏览器资料，也不关闭其他浏览器。完成手动登录或验证后点继续采集，会沿用本次可用模式。窗口关闭后续跑也会在后台恢复，不要求每次手动打开。运行中的采集拒绝人工切换（HTTP 409），避免抢占会话。模式切换有独立锁；旧锁或会话身份变化不会被强行覆盖。除了已授权的后台403自动切换，也可明确点击按钮或执行上述命令打开可见窗口；验证不会自动操作。资料目录、session.json及其私有验证页地址不上传Git或随文献ZIP交付。

以后明确要在线采集时，才执行：

```powershell
.\.venv\Scripts\python.exe scripts/collect_cnki.py --keyword 温经汤 --all --execute --extract
```

不指定`--limit`时默认按关键词遍历全部结果页，`--all`只是显式写出同一模式。关键词可以是方剂名或单味药材名；不按候选疾病二次筛选、不把方剂拆开混采。采集和分析只关注标题、完整摘要，作者/日期/来源/链接用于去重与追溯，不下载或阅读全文，不额外查询期刊影响因子。

全量模式必须保存`collection_progress.json`：每页实际总数、连续页码、每个检索位置对应的题录编号/标题/知网链接、采集状态，以及是否还有下一页。执行器核对页码和位置连续、总数一致、题录可对应、末页无下一页且无失败记录后才发布。完整进度也随`papers.json`交付。范围仅指采集当时该关键词、当前检索入口可访问的结果，不能称为知网所有相关论文均已穷尽。

正常详情页仅提供省略号结尾的摘要节选、且没有可展开内容时，原文保存在`abstract_excerpt`，`abstract=null`、`abstract_status=excerpt_only`，进度明确为`title_only`并说明原因；关系分析仅使用标题，不把节选当作完整摘要。图书没有论文摘要时保留题名及`no_abstract`说明。网页展示这些说明和节选，完整检索记录不等于每条都有完整摘要。页面加载失败、未展开的“更多”或真正验证不会改称无摘要。

网站每页20条不是采集上限，也没有100篇程序上限。需限量试采时可显式传`--limit 5`，这只限制本次新增篇数；旧版准备的限量任务续跑仍沿用原限量。`--extract`额外调用同一模型分析新论文的标题摘要。文献疾病列表不设Top-N，后端返回及前端展示全部关联，数据库查询的Top-K不限制该列表；篇数排序规则不变。

任务保存在`local/agent/cnki-collection/`。网页分阶段执行时，`collector.lock`只保护知网采集及校验，`analysis.lock`保护模型抽取、目标版本核对和manifest发布；不同关键词允许一个采集与一个分析重叠，同一时间各最多一个，分析仍串行。直接调用及CLI默认全任务持有两锁，显式续跑也会同时检查两锁，外部或遗留锁不认领、不删除。验证/限流、漏页、采集中总数变化、单次模型进程超时（40分钟）、引用无法核对或目标版本变化时保留进度，不发布为全量完成；`--resume <任务编号> --execute --extract`可显式续跑。续跑不能同时重设关键词、范围或模型。成功后更新本项目数据及清单；旧论文和旧分析快照不回写。
