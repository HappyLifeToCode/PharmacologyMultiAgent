# 研究问答与模型 API

## 审查修复（2026-11-05）

文献网页任务在接受启动或续跑时即固定模型配置，包括排队期间；切换 API 只影响后续新任务/新续跑。对话默认全量采集不会把已有快速包视为完整结果；若未允许联网则明确提示范围不足，已有缺抽取的快速包也不能只补分析就当全量。对话快照及模型汇总保留 collection 范围；页面显示已记录的原始总数、实际采集位置数，并对部分/快速结果提示。三种模型协议均不再按 24,000 字符静默截断，服务端实际截断仍沿用警示。

## 会话与文献图谱（2026-11-04）

鼠标移到侧栏会话时点击铅笔可修改会话名，名称保存在当前浏览器。鼠标移到用户或助手消息时，消息左下角出现复制按钮；键盘聚焦和触屏也可使用。

CNKI “查看证据”中的“图谱形式”支持勾选流程图、三元组或两者。三元组为已保存的“原文干预—原提取关系—原文疾病”，关系缺失时不补写；点击图中节点查看论文、原句和原记录链接，医学关系仍需复核。点击图谱右上角的小图标按钮可打开放大视图；按钮固定在可视区域右上角，不随图谱横向滚动。光标不再显示放大镜，也不再依赖空白点击；放大后仍可点击节点查看引文，使用“关闭”按钮或 Esc 返回。现有流程图和导出功能保留。

## 对话 CNKI 采集与实时用时（2026-11-02）

研究问答已接入 `collect_cnki_literature`：模型为明确的方剂/药材/疾病选择关键词，本地已有资料就复用；仅缺抽取则安排分析，缺文献且允许联网时关联既有 CNKI 全量标题摘要采集。任务完成后读取正式发布的本地包、生成有来源的候选汇总并继续回答。模型调用仍使用统一 API；浏览器访问、登录与验证码纪律不变。本次未加入 STRING/CytoNCA/DAVID 自动调度。

输入框可选“仅 CNKI / 综合来源 / 按会话与问题”。明确的“只查CNKI”等限制会收紧为 CNKI；该范围在会话中沿用，选择综合来源可解除（问题再次明确限定时仍收紧）。仅 CNKI 时不向模型提供其他来源工具，服务端也拒绝越界调用，旧会话中的非 CNKI 证据不进入本轮来源/引用。缺少知网数据不会自动替换为其他数据库。

采集等待使用 waiting_cnki 状态，单独显示采集、排队、分析及实际条数；等待期间不轮询模型，不占两个问答计算槽。问答计算仍限3分钟，采集等待不计入该预算；等待本身最多8小时，超出时转为需处理，不将其视为研究失败或无证据。登录、验证码、失败、中断转为 needs_attention；页面可打开专用窗口，处理后点击“继续采集并回答”。服务重启后显式续跑，不自动认领旧进程或清理外部锁。

停止本轮回答只停止等待/生成，不自动取消可能共享的采集；“停止采集与回答”会请求停止关联采集，页面明确提示会影响其他等待该关键词的会话。相同关键词沿用已有任务管理器的共享规则。新建采集绑定本轮模型配置；复用的既有任务保留其原模型，显式续跑采用当前选择。

问答和知网任务分别显示每秒更新的真实用时；排队使用 queued_at，本次运行使用 started_at，完成/暂停后用 finished_at 冻结。计时只在浏览器刷新文字，不产生模型请求或重新启动任务。知网长任务不是按普通问答3分钟算作超时。

完整候选列表在回答下方展示，完整文献结果可下载 JSON，快照保存到 `local/assistant/cnki/<request_id>/<snapshot_id>.json` 并校验 SHA-256。模型上下文只提供前40项汇总和最多6篇代表性论文，范围显式标注；界面和下载保留全部程序候选，不将抽样冒充全量阅读。引用存在性检查仍不等于医学关系已验证。

新增接口：`POST /api/assistant/runs/{id}/cnki/resume`、`.../cancel`，只接受空对象；`GET /api/assistant/runs/{id}/cnki-result` 下载该问答登记并校验的快照。原始科研数据、历史快照和凭据不随代码提交。定向检查使用模拟采集与模型，不代表真实知网在线验收通过。

## 回答表格与默认联网（2026-11-02）

回答现在用安全 DOM 渲染 Markdown 表格、标题、列表、代码块和加粗；表格单元格中的证据编号仍可点击。兼容复制时行首被转义为 `\|` 的表格，单元格内部转义的竖线不拆列。代码块中的表格源码仍保持源码。窄屏表格在自身区域横向滚动，不撑宽整页；不执行模型输出中的 HTML 或脚本。旧回答重新读取即可获得新展示，原归档文本和导出不改写。

“查询设置”增加“研究问答默认允许联网检索”，未设置时默认开启，可保存为关闭。刷新页面/新建会话使用保存值，输入框旁的开关可临时覆盖，提交时把实际选择写入本轮请求；运行中的任务和历史回答权限不变。此偏好保存在当前浏览器，只控制资料检索权限；打开开关本身不会启动采集，模型明确调用 CNKI 工具时才可能启动；直接 API 请求未提供 network 时仍默认关闭。

无来源引用的普通回答使用中性来源说明，不再统一显示黄色科研警告。整理用户原文无需为了凑引用而检索；新增医学事实仍需证据核对。虚构引用、截断和执行错误仍保留警示；这一展示调整不构成事实验证或意图自动验收。

## 全项目统一模型入口（2026-11-02）

页面当前选中的 API 现用于**所有生产 LLM 调用**：研究问答与联网检索后的分析、CNKI 标题摘要关系抽取、疾病名称翻译、工作台六角色核验和模型诊断。共同入口为 `pharm/llm.py`，协议适配仍在 `pharm/chat/provider.py`。无配置/无凭据即明确失败，不调用旧 Codex CLI，也不回退到固定模型或其他服务。

一次问答、一次文献执行/续跑、一次翻译或一次流水线启动时，在内存中锁定选中的配置；用户切换后只影响新任务和新的续跑，不让正在执行的批次或多个核验角色混用模型。独立 CLI 进程不能读取主服务的临时内存密钥，需要使用 Windows 加密保存。fixture 和 agents=false 仍保持原有不调用核验模型的边界。

模型来源记录只包含模型、配置 ID、协议及不含密钥的配置指纹，不保存 API 地址或密钥。翻译缓存按该指纹区分；Agent 阶段签名加入模型指纹；文献已完成的抽取片段继续复用并保留各自来源，旧片段未记录模型时标记 legacy_unknown，不将缓存冒充由当前模型重算。运行记录中的 llm_attempts 只表示各次执行采用的配置，不覆盖历史科学产物。

这里统一的是模型服务，不是新建自动研究流程：CNKI 网页仍由程序采集，网络/富集仍由既有程序执行。统一 API 本身不扩大工具范围；后续 CNKI 编排已在上方章节单独接通，通用网页 Agent 和网络/富集自动调度仍未接入。

## 多配置保存与 Codex 中转（2026-11-02 补充）

模型窗口增加“已保存配置”、配置名称、“新增配置”和“从本机 Codex 导入 icrc”。保存后按名称切换，不需要重新输入密钥。Windows 新配置默认加密保存；“仅本次服务”仍是可选项，选此项时重启后需要重填密钥。选择另一个服务地址预设会创建新草稿，不覆盖已有配置。清除密钥仅影响当前所选配置。

多配置保存在 **`local/assistant/model-profiles.json`**，各配置分别保存地址、模型、协议、执行设置和 DPAPI 密文，活动项由 active_id 选择。旧 `model.json` 只作为首次迁移来源，迁移保留其原始密文，不改写旧文件。切换配置只更新活动编号，不解密重写其他配置的密钥。新后端以多配置文件为准，旧版服务需用户重启才能使用新配置。

显式点击导入时，只读取本机 Codex 的 icrc provider、模型及其声明的认证来源：优先指定环境变量，再看配置中的显式 token，必要时使用 auth.json 的 OPENAI_API_KEY；不导入 OAuth 登录 token，不复制整个 Codex 配置，也不修改 Codex 文件。保存时加密，接口不返回密钥或密文。重复导入同名、同地址的 icrc 配置更新原项，不无限新增。

普通 Responses 与 Codex 兼容中转分别处理。Codex 兼容模式使用顶层 instructions、stream=true、store=false，并读取 SSE 的 completed/incomplete 事件，保留工具调用和后续结果流程；推理强度沿用导入配置。此类中转不发送标准 max_output_tokens，输出限制以中转支持为准，本机仍有时间与响应大小限制。可信内网 IP 的 HTTP 连接需要显式允许，并禁用环境代理，避免把内网认证请求送往代理；公网仍要求 HTTPS。实际内网地址和密钥不写入共享文档或代码。

新接口：`POST /api/assistant/config/select` 选择 profile_id；`POST /api/assistant/config/import-codex` 仅接受空对象。原 config GET 返回活动配置和不含密钥的配置列表，POST 可用 profile_name/new_profile/profile_id 保存或新增。

本机 icrc 已按 Codex 当前模型完成一次真实的极短连接检查并收到文字回复。这只证明连接与响应格式可用，不代表真实科研流程已验收。已核对旧配置文件不变、配置切换不改密文、新进程可读取加密凭据；源码与可提交文件中未发现导入的真实密钥或中转 URL。`local/` 整体被 Git 忽略，另外添加 model-profiles 文件名排除规则。不要使用 `git add -f` 强行提交本机配置；Git 忽略不是访问控制。

## 页面使用

1. 用原启动命令启动项目，打开首页，点击右上角“配置模型 API”或侧栏“模型与 API”。
2. 填写 Base URL、接口格式、服务商实际模型 ID 和 API Key。支持 Chat Completions 兼容服务，以及 OpenAI Responses；部分 OpenAI 新模型的工具调用需要 Responses。服务地址下拉仅填常见地址，不自动猜测账号可用模型。
3. 选择仅本次服务运行保存密钥，或 Windows 加密保存。保存后可做连接检查；检查会发送一条极短的真实模型请求，可能产生服务商费用。HTTP 可连接不等于工具调用或研究质量已验证。
4. 选择“研究问答”并提问。默认允许“联网资料”，仍优先使用本机已导入文献与研究数据，必要时允许模型使用 Europe PMC 搜索；可以在查询设置中保存默认关闭，或在输入框临时关闭。远程模型 API 本身仍需要网络，关闭联网资料不是离线模型模式。
5. 回答中 `[E1]` 等编号可展开对应资料。证据来源、执行过程与 JSON 导出随问答保存；可以连续追问。若已有数据库查询结果，同会话最新的研究编号会随问答交给后端读取。
6. 切换“数据库查询”继续使用原方剂/药材→疾病、疾病→药材流程。同名异方或疾病歧义仍由原选择器处理。问答遇到组成歧义时提示切换确认，不代替研究者选择。

推荐用现有 prim 环境启动：

```powershell
cd D:\PharmacologyMultiAgent
& D:\Anaconda\envs\prim\python.exe server/app.py --port 8766
```

已运行旧服务时，需要在用户原终端停止并重新启动后刷新。助手不自动启停用户的 8766 服务。

## 本轮工具范围

| 工具 | 行为 |
| --- | --- |
| list_local_resources | 列出本地 CNKI 关键词与最近20份正反向研究归档 |
| search_local_literature | 检索本地标题摘要、校验 papers.json 的 SHA-256，返回真实文字与来源 |
| search_online_literature | 从 Europe PMC 查询真实题录及可用摘要，保留 PMID/DOI、检索式与来源链接 |
| read_evidence | 读取本会话已取得证据的可用文本，明确截断与未读全文范围 |
| read_research | 读取已有研究前5个候选和部分证据记录；可从回答回到原结果与图谱 |
| query_pharmacology | 通过既有可取消子进程管理器执行 known-only 本地双向查询，最多返回5项 |

此阶段本地文献检索是关键词检索，由 LLM 组织检索词和解释结果；未接入向量库或通用 PDF 文件上传。单次最多扫描20个语料目录、累计30MB题录，每文件最多10MB；超限时明确 partial_scan，不宣称完整覆盖。论文文本最多保存16000字符，传给模型的首轮摘要更短；需要时可读证据全文段落，仍不意味着获取了论文全文。

药理工具要求已存在 BATMAN 必需本地文件，不自动从官网下载。缺失数据、零结果、输入歧义和工具失败均原样返回限制，不编造替代研究结果。图谱、统计和评分由原程序计算，模型负责解释。

**模型设置作用域**：本页 API 统一用于全部生产模型功能，包括 CNKI 采集后的标题摘要抽取、病名翻译和工作台多 Agent 核验。问答可读取已有 CNKI 文献，也可按模型工具调用和联网权限关联 CNKI 全量采集；综合范围可使用 Europe PMC。尚未提供任意网页抓取、网络/富集自动编排或自主修改研究参数。

## 调用与证据纪律

模型工具调用由服务端白名单及参数校验约束，不能执行任意命令或任意路径读取。网络检索仅访问固定 Europe PMC 主机；不会因模型生成了某个 URL 就打开该地址。来源材料被视为资料，不接受其中的提示词作为系统指令。

每条证据保存稳定会话编号、原文、来源、获取时间、原始链接及适用的源文件哈希。回答引用必须对应已有编号，不存在的编号替换成“未核验引用”并提示。**这只核对编号存在，不自动证明引用支持对应医学结论。** 没有引用的回答标明为通用解释或待核实分析；临床、动物、计算预测及传统记载仍需区分。

默认3轮工具规划，可配置1—5轮；每个问题最多8次实际工具执行，并预留最后一轮生成回答。相同工具参数在本轮复用，避免重复调用；每条问答的主要执行流程限3分钟，到限保留已经取得资料。单次模型响应限2MB，单次文献响应限3MB；未完成回答显示为未完成，不把工具成功等同于科研任务成功。

同会话同时只允许一条问答，全服务最多两条。请求编号具备幂等性，同编号不同请求拒绝。刷新通过 GET 恢复，不重发 POST。关闭页面后问答仍受服务端3分钟预算约束；可在页面明确停止。**停止不能撤回已发送给模型服务的请求，也不能保证服务商不会计费**，但不会再继续后续工具循环。服务重启后旧运行标为中断，不冒充仍在执行。

最近6轮问答正文作为上下文，近期12条证据摘要进入下一轮，其余已保存证据可按编号读取；每会话最多80条证据。达到上限提示新建会话。历史数据库结果不会整体发送给模型，只读取有限候选及必要证据，保留截断范围。

## 配置与数据保存

- `local/assistant/model.json`：非秘密模型配置和可选 DPAPI 密文。仅本次服务密钥只留在进程内存；重启后需重填。加密保存绑定当前 Windows 用户/电脑，不能直接复制给对接方使用。
- `local/assistant/runs/<request_id>.json`：问题、状态、工具过程、回答、证据、引用检查和模型名称。
- `local/assistant/sessions/<session_id>.json`：有限上下文和证据记录。
- 浏览器保留会话列表和运行编号，完整回答与证据从本机归档恢复；不会把 API Key 放进 localStorage。清除浏览器列表不删除本机归档。
- 密钥不返回给浏览器、不写入工具日志或回答导出；模型服务报错只展示经过整理的信息，不回显服务商原始错误正文。切换 API 地址且未重新输入密钥时，旧密钥不继承到新地址。

提问和工具选中的资料会发送给用户配置的模型服务。使用自有或远程模型时，需按资料性质选择合适的服务；本机保存不代表从不外发。远程 API 地址要求 HTTPS；仅本机模型允许 HTTP。页面设置通过现有本机访问与跨站校验保护。

## 实现位置与接口

- `pharm/chat/config.py`：配置、DPAPI 和密钥作用域。
- `pharm/chat/provider.py`：Chat Completions / Responses 适配、超时及错误整理。
- `pharm/chat/tools.py`：有限研究工具与证据构建。
- `pharm/chat/engine.py`：工具循环、预算、会话、取消、归档与引用编号检查。
- `server/assistant_api.py`：`GET/POST /api/assistant/config`、`POST /api/assistant/config/test`、`POST /api/assistant/runs`、`GET /api/assistant/runs/{id}`、`POST /api/assistant/runs/{id}/cancel`。
- `server/static/assistant-ui.js`、`assistant.css`：模型配置、问答消息、来源与过程视图，复用原 chat 页面。

Responses 的工具结果通过 function_call_output/call_id 回传，并保留模型返回的 reasoning items；不向用户展示内部推理、不将其当证据。实现参考已实际打开的 [OpenAI Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。Chat Completions 使用标准 tool_calls/tool_call_id；具体服务商和模型仍需实际验证。
