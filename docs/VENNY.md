# Venny 2.1.0 交集步骤

本项目按研究原文使用 [官方 Venny 2.1.0](https://bioinfogp.cnb.csic.es/tools/venny/)
完成药材靶点与疾病靶点的交集。入口为 `pharm_demo/venny.py`，由执行器在两路靶点通过检查后调用。

## 执行与验收

1. 保存两侧已规范化、去重的完整靶点输入。
2. Playwright 启动独立无头 Chromium，访问官方页面并核验页面版本。
3. 在页面中填写两个列表及名称，等待 Venny 更新计数。
4. 点击药材独有、疾病独有和共同靶点三个区域，读取页面返回的原始文本。
5. 保存 Venny 页面生成的原始 PNG 和页面截图。Python 独立核对集合、计数和唯一性；全部一致才发布 `intersection.json`
   与 `genes.txt`，供 STRING 和 DAVID 使用。

该阶段是多 Agent 流程中的浏览器工具步骤，没有额外模型会话；六种角色、七个独立模型会话、九个阶段的结构不变。浏览器由 Python
Playwright 直接控制；其他 Agent 使用的 Playwright MCP 仍固定为 0.0.64，启动超时 120 秒。

## 产物

每次尝试保存在 `runs/<run_id>/intersection/attempt_<nn>/`：

| 文件                                 | 内容                             |
|------------------------------------|--------------------------------|
| herb_input.txt / disease_input.txt | 两侧实际填入 Venny 的完整靶点名单           |
| venny_results.txt                  | Venny 三个集合区域返回的原始文本            |
| venny.png                          | 官方页面生成的原始 PNG，未经过本地重绘          |
| venny_page.png                     | 输入、图形及选中交集结果的页面截图              |
| venny_execution.json               | 实际网址、版本、访问时间、操作记录、输入/产物哈希及核对状态 |
| intersection.json / genes.txt      | 验收通过的 Venny 结果与下游共同靶点输入        |
| sources/official_page.html         | 本次访问的原始页面，仅本地留存                |
| browser/traces/venny.zip           | 浏览器操作 trace，仅本地留存              |

真实运行的交集证据按现有规则归档至 `data/pharm/<方名>/03_intersect/`；trace 保存在原始 run
中，不通过工作台公开下载。页面及执行记录保留实际访问日期，不能沿用原文的 2025 年日期。

## 失败与演示边界

网页不可达、版本不符、页面返回格式异常或交集核对不一致时，步骤失败并保存可取得的现场证据；不自动换成本地图，也不继续正式网络或富集分析。修复后重试会新建
attempt，保留旧证据。

两份非空输入没有重叠时，Venny 返回零交集，正常保存，下游跳过分析。若任一上游名单本身为空，当前适配器明确报告无法进行两列表执行，不生成占位图。

真实模式和测试模式都实际访问 Venny，因此新测试运行也需要网络及 Playwright Chromium。测试模式使用固定合成输入，图中标注
SYNTHETIC / SYNTH，只证明工程流程；不能说明五库真实药理数据已经齐备。组会离线展示可使用已导出的 HTML 报告。

接入前的历史运行保留原本的 Python/Matplotlib 交集记录；不会因更新界面被追认成已使用 Venny。
